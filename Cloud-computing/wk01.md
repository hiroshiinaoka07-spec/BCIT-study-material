## A brief intro to Cloud Computing

> Cloud computing is a model for enabling ubiquitous, convenient, on-demand network access to a shared pool of configurable computing resources (networks, virtual machines, storage, applications, and services) that can be rapidly provisioned and released with minimal management effort or service provider interaction.
   —National Institute of Standards and Technology

### How does cloud computing work

The cloud computing service model is based on the sharing of on-demand resources. Cloud services commonly use consumption-based pricing, allowing organizations to pay for resources based on their usage. Keep in mind that pricing models vary significantly between services. 

### Why do organizations use cloud computing in their infrastructure

- Flexibility
	- Users can access cloud services from almost anywhere in the world
	- Most cloud services providers offer a suite of services that integrate well with each other to meet your business needs
- Security
	- Cloud services providers generally have exceptional teams working specifically on security. 
- Efficiency
	- New resources can quickly be created, allowing teams to experiment and push updates quickly
- Cost
	- Depending on your organizations needs, costs are often lower than maintaining your own hardware and services.

### Cloud computing components

#### Servers

Servers are powerful computers that a cloud service provider or other organization run in their data centers. Often servers run multiple VMs giving users access to a Virtual Private Server(VPS).

#### Networking

> Networking is the cloud's capability to connect different data storage, applications, microservices, and other workloads across different servers and data centers. To enable cloud connectivity, cloud providers use networking equipment—such as load balancers and network switches—so you can establish communication channels and manage traffic in the cloud environment. Meanwhile, developers use load balancing to reduce network latency and improve application performance when traffic demand grows.
> -- [AWS What is cloud infrastructure](https://aws.amazon.com/what-is/cloud-infrastructure/)

#### Storage

Storage is persistent data stored on cloud infrastructure. Often cloud storage can be accessed from devices on the internet. Cloud storage is often scalable, so users can expand its size, region and availability.


### Types of cloud computing deployment models

#### Public cloud

>[Public clouds](https://cloud.google.com/learn/what-is-public-cloud) are run by third-party cloud service providers. They offer compute, storage, and network resources over the internet, enabling companies to access shared on-demand resources based on their unique requirements and business goals.

#### Community cloud

A community cloud allows organizations with similar needs to share infrastructure. It can be managed by one or more of the organizations or a third party.

Generally the difference between public and community is exactly what it sounds like. A community cloud generally comes about when organizations with similar needs pool their resources to benefit all organizations in the community.

#### Private cloud

> A private cloud is a [cloud computing](https://aws.amazon.com/what-is-cloud-computing/) environment dedicated to a single organization. Any [cloud infrastructure](https://aws.amazon.com/what-is/cloud-infrastructure/) has underlying compute resources like CPU and storage that you provision on demand through a self-service portal. In a private cloud, all resources are isolated and in the control of one organization. So, the private cloud is also called the _internal_ or _corporate_ cloud.
> -- [AWS, What is a Private Cloud](https://aws.amazon.com/what-is/private-cloud/)

On-premises doesn't necessarily mean private cloud. On-premises only means that the organization is managing their own local infrastructure.

A private cloud also doesn't have to be on-premises.
#### Hybrid cloud

>[Hybrid clouds](https://cloud.google.com/learn/what-is-hybrid-cloud) combine public and private cloud models, allowing companies to leverage public cloud services and maintain the security and compliance capabilities commonly found in private cloud architectures.

Amazon Web Services (AWS) is a public cloud. By combining your on-premises data center with AWS, you are building a hybrid cloud.

### Cloud computing service models

#### IaaS

> [Infrastructure as a service](https://cloud.google.com/learn/what-is-iaas) (IaaS) offers on-demand access to IT infrastructure services, including compute, storage, networking, and virtualization. It provides the highest level of control over your IT resources and most closely resembles traditional on-premises IT resources.

Things like VPS(VM) services (AWS EC2)
Most of the services AWS offers fall under the category of IaaS.

#### PaaS

> [Platform as a service](https://cloud.google.com/learn/what-is-paas) (PaaS) offers all the hardware and software resources needed for cloud application development. With PaaS, companies can focus fully on application development without the burden of managing and maintaining the underlying infrastructure.

Things like [Vercel](https://vercel.com/)

#### SaaS

> Software as a service (SaaS) delivers a full application stack as a service, from underlying infrastructure to maintenance and updates to the app software itself. A SaaS solution is often an end-user application, where both the service and the infrastructure is managed and maintained by the cloud service provider.

Things like Google Docs

### Cloud computing regions

#### Region

A geographic area containing cloud infrastructure. For example, AWS has regions such as `us-west-2` (Oregon) and `ca-central-1` (Canada).
#### Availability zone

An isolated location within a region containing one or more data centers. Cloud providers use multiple AZs within a region to improve availability and fault tolerance.

For example the `us-west-2` region has multiple availability zones `us-west-2a, us-west-2b...`

> Each AWS Region has at least three Availability Zones. This helps you to design highly available applications on AWS.
> -- [AWS Availability Zones](https://docs.aws.amazon.com/global-infrastructure/latest/regions/aws-availability-zones.html)
### Related terminology

### Multitenancy

**Multitenancy** means that multiple customers (tenants) of a cloud provider use shared computing infrastructure and resources. The tenants may share physical servers, storage, networking, and software, while logically operating as separate environments. Each tenant's data and resources are isolated from those of other tenants.

Cloud services generally maintain information about each tenant, such as its identity, configuration, permissions, subscription, and resource limits. This information can be used to provide tenant-specific functionality and enforce access policies. Cloud providers use a combination of access controls, virtualization, network isolation, encryption, and other security mechanisms to prevent one tenant from accessing another tenant's resources or data.

#### IaC (Infrastructure as Code)

> Infrastructure as code (IaC) is the ability to provision and support your computing infrastructure using code instead of manual processes and settings. Any application environment requires many infrastructure components like operating systems, database connections, and storage. Developers have to regularly set up, update, and maintain the infrastructure to develop, test, and deploy applications. 

> Manual infrastructure management is time-consuming and prone to error—especially when you manage applications at scale. Infrastructure as code lets you define your infrastructure's desired state without including all the steps to get to that state. It automates infrastructure management so developers can focus on building and improving applications instead of managing environments. Organizations use infrastructure as code to control costs, reduce risks, and respond with speed to new business opportunities.

Things like Terraform
