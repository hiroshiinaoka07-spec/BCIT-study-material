How to deploy a child domain controller and a secondary domain controller 
Why do we need Child Domains? 
For domain administrators, they may need to create child domains for managing and maintaining 
network hierarchy. In a domain environment, child domain can be implemented on separate 
departments and branches with the purpose of helping domain administrators to define security 
and resources boundaries. For example, you can apply different group polices for child domains 
without affecting parent domain polices (Note: You will have a better understanding of why 
child domain is important in a domain environment after you learn group policy).

Task 2: Secondary Domain Controller 
Domain controller can be divided into two categories: Primary domain controller and back 
domain controller (BDC) or secondary domain controller. If the primary DC fails and there’s no 
backup, users will not be able to gain access to network. When a user attempts to log in, the 
software contacts the primary DC. If the primary DC is unavailable, it then contacts the backup 
DC. In addition, we need an additional domain controller to balance the load. For example, BCIT
has 8 domain controllers for balance the load and increase fault tolerance. Generally, you have to
deploy at least two domain controllers for your organization.
